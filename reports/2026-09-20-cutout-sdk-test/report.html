三、真实场景样张（原片 → 抠图）

① 平铺拍摄 · 杂色渐变床单

模拟随手拍：渐变背景 + 噪点 + 砖红 T 恤（带描边与中央白色印花）
主体 alpha 255背景角落 alpha 0 发现：中央大面积白色印花内部被误判透明（见第四节 2）

② 挂拍 · 木地板背景

深蓝 T 恤 + 顶部挂钩，暖色木纹渐变背景
主体 alpha 255背景角落 alpha 0边缘无背景色晕边（ADR-005）

③ 低对比 · 白衬衫浅灰背景

最难场景：前景/背景亮度差极小（ΔRGB ≈ 20）+ 弱描边
主体 alpha 254背景角落 alpha 0 锐化后边缘干净（原残留 1–2px 灰晕已消除）

④ 人穿衣服 · 预期「连人抠出」

头部 + 双臂 + 衣服：显著性分割不区分人/物；锐化窗下头部/手臂（弱显著部分）被明显削切
衣身 alpha 255背景角落 alpha 0 头部/手臂残缺（掩码中值被锐化窗压低，见第四节 3）

四、发现与已知边界

  • 背景色晕边已修复（ADR-005 边缘锐化窗）。掩码软边像素的 RGB 仍是背景色，纯软边输出会在主体周围 形成「背景色描边」（修复前挂拍场景有一圈明显木色晕边）。在 min-max 拉伸后增加锐化窗 （归一化掩码 <0.35 判背景、>0.85 判主体、之间线性过渡），半透明带收窄后晕边基本消除，残留仅 1px 级。 对硬边衣物主场景收益明确。
  • 大面积低频印花可能被误伤，锐化后更明显。场景①中衣身中央的纯白矩形印花（零纹理）掩码值低， 会被误判为背景挖出透明洞。真实衣物印花通常带图案纹理，影响面小；兜底是交互上「前后对比 + 一键放弃」。观察项。
  • 人穿衣服场景建议产品上放弃抠图。u2netp 是显著性分割，不做「只抠衣物」；且锐化窗会削切 掩码中等的弱显著部分——场景④中头部/手臂明显残缺。结论：录入 UI 对该形态照片给出「不建议去背景」提示， 或后续引入 human parsing 模型（远期演进）。
  • 桌面数字 ≠ 手机数字。213 ms 为 mac arm64 桌面 JVM 热推理；移动端 ARM CPU 预算 0.3–0.8 s/张， 首次调用（建会话）一次性 ~1 s，阶段 B 真机实测回填。

五、覆盖缺口（阶段 B 回填清单）

  • Android 真机/模拟器端到端：Bitmap RGBA 桥正确性、真机耗时、中低端机型内存峰值
  • APK 增量实测（预算 +30 MB 量级：onnxruntime .so ~25 MB + 模型 4.4 MB）
  • 冷启动无回归（启动路径不触碰 onnxruntime 类）
  • 带 alpha WebP 在卡片 / 导出合成长图的渲染走查（透明底不出现黑底）
