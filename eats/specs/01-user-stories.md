# 01 · 用户故事与验收标准

编号规则：`US-XX` 用户故事，`UC-XX` 对应用例/界面（W 编号见 [02-wireframes.md](02-wireframes.md)）。验收标准采用 Given/When/Then。

## 食堂管理

> 「食堂」= 一个吃饭选项：堂食餐厅 / 外卖店 / 一道自做的菜，三类统一建模（ADR-007）。

### US-01 录入食堂
作为用户，我想把一家餐厅 / 一个外卖店 / 一道自做的菜建成条目，记录名称、类型、菜系、位置、照片、评分、标签和总体笔记，作为后续记录与决策的基础。
- **UC**：W3 → FAB → W4
- Given 表单，When 未填名称即点保存，Then 阻止保存并提示名称必填
- Given 类型为「堂食/外卖」，When 点位置栏，Then 打开内嵌选点地图，长按放置 pin，确认后带回经纬度与可选地址文本
- Given 类型为「自做」，Then 位置栏可整体跳过（自做菜默认无坐标）
- Given 选好照片（可多张），When 保存，Then 压缩为 WebP 落盘、条目写入，列表与地图（若有坐标）立即可见

### US-02 编辑/删除食堂
- Given 列表或详情，When 进入编辑，Then 表单数据回填，保存后即时生效
- When 删除，Then 二次确认；确认后该食堂及其全部 Visit、双方照片文件一并删除

## 记录一次吃

### US-03 记一笔（Visit）
作为用户，吃的时候我想用最少操作记下「今天吃了这家」，并可附评分、花费、感想、照片。
- **UC**：W5 / W1 结果卡 → W6
- Given 详情页或抽取结果卡，When 点「记一笔」，Then 弹出 W6：时间默认现在（可改），其余全可选
- Given 提交，Then 创建 Visit，详情页「最近一次吃 / 累计 N 次」立即更新
- Given 详情页时间线，Then 每条 Visit 可删除（其照片一并删除）

## 查看

### US-04 地图总览
- **UC**：W2
- Given 地图页，Then 有坐标的食堂按类型着色显示 marker（堂食=红 / 外卖=琥珀 / 自做=绿）
- When 点 marker，Then 底部滑出摘要卡（名称 · 评分 · 最近一次 · 次数），点卡进详情
- Given 无坐标的食堂，Then 不上地图；地图页显示「N 条未上地图」入口，点击跳列表并筛出这些条目
- 地图瓦片在线加载并缓存；无网络时显示缓存底图，marker 不受影响

### US-05 列表总览
- **UC**：W3
- Given 列表页，Then 默认按「最近一次吃」倒序；可切换 评分 / 累计次数 / 名称
- Given 筛选条，Then 类型 chips（堂食/外卖/自做）+ 标签筛选生效
- Given 搜索框，Then 按名称/笔记关键字过滤
- 每行展示：名称 · 类型图标 · 评分 · 最近一次相对时间（「3 天前」/「没吃过」）· 累计次数

### US-06 详情与时间线
- **UC**：W3/W2 → W5
- Given 详情页，Then 展示基本信息、照片横滑、派生统计（最近一次 / 累计次数 / Visit 平均分）
- Then Visit 时间线按时间倒序：日期 · 评分 · 花费 · 感想 · 照片（可横滑）
- 提供入口：记一笔 · 编辑 · 在地图上看（有坐标时）

## 外部链接

### US-08 链接记录与快速跳转
作为用户，我想给食堂贴上美团/大众点评的分享链接（店铺页或套餐页），之后一键跳回，省去在 App 里重新搜店。
- **UC**：W4 录入 · W5 跳转 · W1 结果卡直达
- Given W4 表单，When 粘贴链接，Then 自动识别来源（美团/大众点评/其他）并以 chip 展示，可加简短标签（如「双人套餐」）、可删除；重复粘贴同一链接时去重
- Given W5 详情，Then 链接以 chip 列表展示（来源徽标 + 标签），点击经系统 ACTION_VIEW 打开（App Links 命中时直接拉起对应 App）
- Given W1 结果卡，Then 该食堂有链接时结果卡上直接给出跳转入口（转完即点，直达下单页）
- Given 系统无可处理该链接的组件，Then toast 提示而非崩溃

## 决策

### US-07 今天吃啥（卡组抽取，it-003 修订）
作为用户，饭点我想快速翻看候选、或让 App 随机替我拍板，并且别老抽到刚吃过的。
- **UC**：W1
- Given 决策页，Then 候选池 = 过滤后的食堂：类型多选（默认全选）、排除标签（忌口，如「辣」）、「排除最近 N 天吃过的」开关（默认 14 天）
- Given 候选卡片，When 左滑或右滑，Then 飞出当前卡、下一张晋升（可快速浏览全部候选）
- Given 候选 ≥1，When 点「随机抽一张」，Then 卡组按拍加速—减速翻张（老虎机式）落定于随机一张（无权重），结果条弹出并撒彩屑
- Given 结果条，When 点「就吃这个」，Then 打开 W6（预填该食堂与当前时间）落账；When 点「再抽」，Then 重新抽取
- 卡片展示：照片（或类型 3D 插画）、名称/类型/菜系、评分、上次·次数、标签、下单链接直达、记一笔/详情

## 非功能需求

- NFR-01 冷启动 < 2s；列表/地图交互流畅
- NFR-02 数据写入为原子操作（tmp → rename），进程被杀不丢数据；启动时 JSON 损坏则尝试 .bak 恢复
- NFR-03 深色模式完整适配；视觉遵循 [05-design-system.md](05-design-system.md)
- NFR-04 JVM 单测覆盖 domain 用例（抽取过滤/派生统计/链接来源识别）与 Repository（假实现）

## 统计回顾（it-007）

### US-09 统计回顾页
作为用户，我想在一个页面回看「我平时都吃什么」的汇总数据，而不只靠单店详情的时间线。
- **UC**：W3 标题行 📊 → W7
- Given W7，Then 展示三大数字（总顿数/总花费/去过店数）、最爱 TOP3 横滑卡（次数+均分）、类型占比条、月度节奏 12 柱（峰值高亮）、连续记录天数
- Given 档位切换（今年/去年/累计），Then 全部指标按档位重算；总花费只统计有 cost 的 Visit，无花费数据显示「—」
- Given 空档位，Then 数字为 0/—，生成按钮置灰

### US-10 年度食光长图
- Given W7 点「生成年终食光长图」，Then 生成纵向长图（封面年份 → 三大数字 → 最爱 TOP3 → 类型占比 → 月度节奏 → 照片墙 ≤9 张 → 结尾条），可存相册（Pictures/Eats）与分享
- Given 档内无照片，Then 照片墙整段跳过；预览/存相册/分享为同一版本
- Given 档内无任何记录，Then 按钮置灰并提示

### US-11 好久没去提醒
- Given 开关开启（默认关，开启时请求 POST_NOTIFICATIONS），Then WorkManager 每日检查：去过 ≥3 次、综合评分 ≥4（缺失回退 Visit 均分）、距上次 ≥N 天（默认 90，可选 60/90/180）的食堂，每日至多推 1 条（有照片用大图样式），点击进详情
- Given 上次提醒过的食堂仍有其他候选，Then 先推其余候选
- Given 演示模式，Then 不注册任务、入口置灰提示

## 吃喝玩乐与愿望清单（it-008）

### US-12 分类体系（吃 / 喝 / 玩）
作为用户，我想把看展、桌游、咖啡馆等「吃喝玩乐」都录进来统一决策，而不是只有吃饭。
- **UC**：W4 录入 · W1/W3 筛选 · W2 图例
- Given W4，Then 分类单选 chips（吃/喝/玩，默认吃）；类型 chips 文案随分类切换（吃=堂食/外卖/自做、喝=堂食/外送/自调、玩=出门/在家且不提供外送）
- Given PLAY 分类，Then 「菜系」字段以「说明」示人（同一数据字段）
- Given W1/W3/筛选弹层，Then 分类 chips 生效（全部/吃/喝/玩）；W1 标题随分类动态（今天干啥/吃啥/喝啥/玩啥）
- Given W2 地图，Then marker 与吸顶图例按分类三色：吃=红 / 喝=琥珀 / 玩=紫
- Given 旧版本 JSON（无 category 字段），Then 反序列化为 EAT，行为与升级前一致

### US-13 愿望清单（想吃 / 想玩）
作为用户，我想把种草了还没去的地方单独标记和管理，去了之后自动拔草。
- **UC**：W4 种草开关 · W3 愿望筛选 · W5 愿望态
- Given W4 开启「先种草」，Then 保存后条目带 🌟 愿望标记（仅名称必填，其余全可选）
- Given W3，Then 「🌟愿望」toggle 只看愿望、排序含「种草时间」、行内愿望带 🌟 与「种草 N 天」
- Given W5 愿望条目，Then 显示种草徽章行与「取消种草」入口
- Given 愿望条目落账（记一笔），Then 自动移出愿望清单，snackbar「已移出愿望清单 · 撤销」可恢复原种草时间

### US-14 抽签扩展（今天干啥 + 只抽愿望）
- **UC**：W1
- Given 分类/类型/忌口/最近排除的任意组合，Then 候选池按集合交集过滤；「只抽愿望」开启时候选限定为愿望条目
- Given 抽中结果，Then 结果块横幅与主按钮随分类显示「今天就吃/就喝/就去」「✓ 就吃/就喝/就去，安排！」
- Given 愿望卡，Then 卡面显示「🌟 种草 N 天 · 还没去过」代替上次/次数

### US-15 安排排期（轻量）
作为用户，我想把愿望安排到某天，到当天在抽签页一眼看到。
- **UC**：W5 安排入口 · W1 提示条 · W3 置顶小节
- Given W5 愿望条目，Then 「📅 安排到某天」打开日期选择器（只选日期），可清除安排
- Given 当天有安排条目，Then W1 顶部出现提示条「今天安排：XX →」点击进详情
- Given 未来 30 天内有安排的愿望，Then W3 顶部「最近的安排」小节按日期升序显示（≤3 条）；过期静默回普通愿望序

## US-16 数据包导入导出（it-012）

作为食客，我能把全部食堂与记录（含照片）导出成一个结构化数据包，交给 AI 或其他工具加工后导回，实现批量打标、迁移与备份。

- **UC**：W7「数据」小节 · 系统分享/打开方式直达
- Given W7 点「导出数据包」，Then 生成 `eats-backup-*.zip`（manifest + eats.json + images），完成 snackbar 带 [分享]
- Given 导入，Then 先校验（含 eats 特有规则：PLAY+TAKEOUT 无效 / rating 1–5 / 空 url）→ 预览确认（＋新增 X 家 · ↻更新 Y 家）→ 合并（默认）/ 替换（二次确认）
- Given 错包，Then 拒绝列原因，本地零改动；演示模式置灰
