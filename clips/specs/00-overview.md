# 00 · 业务背景与总览

## 为什么做这个应用

复制过的东西，转眼就找不回来——系统剪贴板只保留最后一条，而且会被下一条复制悄悄覆盖：

1. **找回刚复制过的内容**：一段地址、一句签名、一个配色值、一条命令，两步之前复制的就没了。
2. **常用片段随手粘贴**：取件码、邮箱、常用回复，不该每次重新打一遍。
3. **Mac 与 Android 各装一个**：同一套习惯两端可用，数据各自留在本机。

## 核心价值流

```
捕获（尽量零操作）
  Mac：后台轮询剪贴板，变化即入库（全文去重）
  Android：打开 App 即读当前剪贴板；系统分享菜单可直接存入
        │
        ▼
历史库（本地 clips.json，默认 Mac 200 / Android 50 条，超限自动淘汰；置顶永不淘汰）
        │
        ▼
呼出与检索
  Mac：菜单栏图标 / ⌘⇧V 全局热键 → 搜索面板 → ↑↓ 选中 → ⏎ 复制回（可选自动 ⌘V）
  Android：快捷设置磁贴一键打开 → 搜索/点选 → 复制并返回原应用
```

## 双端实现与功能分工

- **分开实现、各自原生**：Mac 用 SwiftUI/AppKit（菜单栏工具的常驻内存与呼出速度只有原生合适）；Android 用 Kotlin + Compose（复用 wardrobe 技术栈）。见 ADR-001。
- **共享的是契约不是代码**：规格文档与 `clips.json` 数据格式双端一致（ADR-009），一端导出另一端可导入。
- **功能按平台取舍，不追求对齐**：Mac 有全局热键/自动粘贴/开机自启（系统允许后台读剪贴板）；Android 有磁贴/分享入库/复制返回（系统限制下的最优解）；默认容量等参数双端各自设定。

## 关键用户与设备

- 个人自用：一台 Mac（菜单栏常驻）+ 一台 Android 手机。
- 无账号、无服务端、**无网络权限**（Android 不申请 INTERNET），数据全部存本机。
- 剪贴板可能含敏感内容（密码/验证码）：提供「暂停记录」开关与单条/全部删除；不做任何上传。

## 范围外（明确不做）

- 双端数据同步（v1；候选方案见 ADR-006）
- 图片/文件类剪贴内容（后续迭代，届时带条数上限）
- iOS、Windows、Linux 桌面端
- 云端/账号体系（永不）
