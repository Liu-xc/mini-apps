# 01-user-stories — 驿站（posthouse）

> M1 烽火台 / M2 自动哨兵 / M3 邸报，对应 it-001 三个里程碑。

## US-01 一眼看清全部仓库的火情（M1）

**作为** 同时维护多个 git 仓库的开发者，**我想** 在菜单栏看到所有仓库的聚合火情，
**以便** 不用逐仓敲 git 命令就知道有没有积压/断连。

- UC-01-1 菜单栏图标三态：全绿（circlebadge）/ 狼烟（flame+计数）/ 熄火（bolt.slash），聚合规则：任一熄火 > 任一狼烟 > 全绿。
- UC-01-2 下拉菜单逐仓列出：状态图标、仓库名、`分支 ↑ahead ↓behind ✗dirty`。
- UC-01-3 探测数据与 `git status --porcelain` / `git rev-list --count @{u}..HEAD` 一致（验收以对账为准）。
- UC-01-4 轮询周期默认 60s，失败不断电，下一轮自动恢复。

## US-02 手动推送带上网络参数（M1）

**作为** 经常被代理/网络卡住的开发者，**我想** 一键推送并自动带上 HTTP/1.1 + postBuffer 参数，
**以便** 不用每次手敲 `-c` 参数、且不污染仓库自身配置。

- UC-02-1 菜单仓库子项「推送 N 个提交」，只读校验：无远端禁用、无积压禁用、behind>0 拒绝。
- UC-02-2 参数以 `git -c key=value push` 形式注入，日志记录实际命令行。
- UC-02-3 成功/失败均出通知中心 + 日志。

## US-03 断网恢复后白名单仓库自动补推（M2）

**作为** 被「推送悄悄失败」坑过的人，**我想** 指定仓库在远端恢复后自动补推，
**以便** 积压不再过夜。

- UC-03-1 双开关：全局总开关 + 仓库白名单，**默认全关**。
- UC-03-2 硬规则（单测覆盖，违反即视为 bug）：
  1. 白名单外绝不自动推送；
  2. 永不 `--force`；
  3. 永不自动 `pull`/`rebase`/`merge`——本地落后远端（含分叉）只报警不动手；
  4. 远端探测不通不推送，走指数退避（30s→600s 封顶）。
- UC-03-3 网络类连续失败 ≥3 次 → 「疑似代理故障」通知。
- UC-03-4 验收场景：断远端 → 恢复 → ≤1 轮询周期内补推成功；非白名单仓全程不被碰。

## US-04 每晚自动生成一页战报（M3）

**作为** 并行会话满天飞的开发者，**我想** 每晚收到当日 git 战报，
**以便** 快速知道今天干了什么、积压收没收干净。

- UC-04-1 定时（默认 22:30，可配）扫描监控仓当日 `git log`，产出 Markdown 到 `gazetteOutputDir`（默认 `~/Documents/daily-gazette/`，不入公开仓库）。
- UC-04-2 内容：提交合计与分仓分类（feat/fix/docs/spec）、推送事件（自动/手动、提交数）、收官积压、连续活跃天数。
- UC-04-3 同日只生成一次（gazette-dates.json 去重），生成后通知中心报路径。
- UC-04-4 成就规则引擎首发 6 枚（纯规则可回放）：首日点亮/连修三坑/深夜修罗/大部队/清仓大吉/千军一发；档案落 achievements.json，一次性成就不重复发放。

## US-05 CLI 一次性操作（支撑验收与脚本化）

- UC-05-1 `--probe`：同步探测打印 status.json，exit 0。
- UC-05-2 `--push <path>`：手动推送（与菜单按钮同一代码路径）；exit 0 成功 / 3 被安全规则拦截 / 1 失败。
- UC-05-3 `--gazette`：立即生成邸报。
- UC-05-4 CLI 模式不起菜单栏、不启轮询，进程干净退出。
