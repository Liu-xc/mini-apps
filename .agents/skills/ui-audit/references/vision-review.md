# 视觉评审 · analyze_image 用法与评审方法

## 看图的唯一途径

本环境 Read PNG **只返回 CDN URL、不呈现画面**。"看图"= 视觉模型：

```
Read 截图.png            → 拿到 CDN URL（逐字复制）
analyze_image(imageSource=<CDN URL>, prompt=<评审 prompt>)
```

- URL 签名含 `+` 时视觉接口可能 400（`+` 在 query 里被当空格）：先试 `%2B` 编码；仍失败 → 复制文件改新名重新 Read 拿干净 URL。
- 一次调用评**一页**。多页拼 contact sheet 会丢细节，只在"自检线框图有无绘制缺陷"这类粗查时用。

## 评审 prompt 模板（每页填充）

```
这是安卓 App「<App名>」的<页面名>页。界面结构：<从 spec/dump 得到的结构描述>。
请对标 Airbnb/Things/Linear 的 UI 质量标准，严格评审：
1) 信息层级与可读性  2) 间距/对齐/留白  3) 颜色对比度与语义
4) 交互线索（affordance）：第一次用的用户能否明白怎么操作
5) 任何看起来廉价/不精致的地方
输出 P0（阻断体验）/P1（明显问题）/P2（打磨项）分级清单，每条给具体位置描述。
```

要点：
- **把页面身份和结构写进 prompt**——视觉模型不知道这是什么页，喂给它 spec 里的结构描述能显著减少误报。
- 过程态页面（抽取落定、随机结果）单独评，rubric 换成"此状态的呈现是否清晰/有仪式感/下一步操作是否一目了然"。
- 地图类页面要求评 marker 可读性、图例自解释性；表单类要求评保存可达性、必填提示、键盘遮挡。
- 线框图自检的 prompt：逐张查"文字出界/元素重叠/徽标压字贴边/图形畸形"，一行一结论。

## 结果整理

- 每页产出 = 问题数组 [(severity, text)]。视觉模型会重复、会过度引申——**合并去重，保留可定位到具体位置的条目**。
- 视觉结论 ≠ 事实：涉及"功能是否存在/是否生效"的，回到 uiautomator 或源码验证（SKILL.md 阶段 3），把验证结果标进问题条目（"实测确认/代码核对"）。验证不了又高价值的，标注"待复验"。
- 交付给用户内嵌图时 CDN URL 必须逐字复制、约 2 小时过期；原件留在仓库 reports 目录最稳。
