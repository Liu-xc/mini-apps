## 背景与动机

仓库面向「人 + AI 协作者」，实际已有多个协作者并行（`.zcode/`、`.claude/`、`.agents/` 为证）。现状盘点：

- **有消费端**：AGENTS.md 上下文恢复清单（README → DESIGN.md → 常青 spec → 最近迭代 → 代码）。
- **缺生产端**：迭代流程①~⑤ 没有「写回经验」的步骤。教训散落在迭代文件里（xiangqi 超时诊断、wardrobe spec 数字漂移、it-048 连环坑、travel-rpg 报告已知坑……），后续会话不会主动读到，等于每次换会话就丢一次。
- **缺晋级机制**：经验没有「一行规则 → 固化铁律 → 自动检查」的阶梯，也没有淘汰规则——不晋转会膨胀，不淘汰会过期。
- **机器本地记忆不入仓**：会话记忆（如 MiMo 项目记忆）在仓外，跨协作者不可见。经验必须**进仓库**才可共享。

### 方案：四环闭环

1. **记录**：新建根 `LESSONS.md` 经验库——单文件、分四区、一行一条、附出处链接与年月；头部写死条目格式 / 容量 / 晋级 / 淘汰规则。
2. **消费**：AGENTS.md 上下文恢复清单新增必读 `LESSONS.md`（先看规则再动手）。
3. **晋级**：迭代流程新增第⑤步「经验沉淀」（收尾自问，≤3 条）；反复出现或全局性的教训升级进 AGENTS.md（流程类）/ DESIGN.md（视觉类）/ 常青 spec（应用类）；能被脚本/CI 防住的写成自动检查（最高形态）。
4. **淘汰**：失效条目直接删除不留墓碑；每节 ≤15 条，满额先晋级或删除再收新条目。

## 用户故事

（仓库级元迭代无 US 编号体系——根 specs 暂无 `01-user-stories.md`，以 AC 承接验收。）

- 任一协作者接手工作时，能从单一入口（`LESSONS.md`）读到历史教训与行为规则，不必翻遍迭代文件考古。
