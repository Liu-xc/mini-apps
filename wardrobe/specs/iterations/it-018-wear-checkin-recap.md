# it-018 · 穿搭打卡：穿着记录 + 年度衣橱 + 好久没穿提醒

- **状态**：待确认（Leo）
- **提案日期**：2026-09-20
- **范围**：新增 WearLog 穿着打卡实体（数据地基）→ 衣橱统计回顾页（W9）+「年度衣橱」长图 + WorkManager 本地「好久没穿」提醒；（可选）Item 价格字段 + CPW
- **姊妹迭代**：eats it-007（统计回顾），两案同期提出、互相独立可分别立项
- **线框图**：[reports/2026-09-20-stats-recap-wireframes/](../../../reports/2026-09-20-stats-recap-wireframes/)（打卡态 + W9 回顾页 + 长图版式，确认后落 02-wireframes.md）

## 背景与动机

穿搭沉淀了「存过哪些套」，但没有「哪天真穿了」。缺了穿着事件这一环，三件事都做不了：年度衣橱报告没素材、单品利用率/闲置无从判断、「这件大衣多久没穿了」全靠记忆。本迭代先补地基（打卡，一次点击的成本），再在其上做统计回顾——与吃啥 it-007 完全对称：吃啥有「好久没去」，衣橱有「好久没穿」。

## 方案

### 阶段A · 穿搭打卡（数据地基）

- 新实体 `WearLog`：`id` · `personId` · `outfitId` · `at`（epoch millis，默认现在，可改当日）。**允许同日多条**（早晚换装是真实场景），展示按日聚合。
- 入口：W7 穿搭详情主按钮区新增「👔 今天穿了这套」；当日已打卡则显示「✓ 9/20 已穿」再点弹出「再记一次 / 撤销今日」。打卡成功轻反馈动画（缩放 + 一次性粒子，不堆彩屑）。
- 级联（Repository 不变量追加）：删除 Outfit → 级联删其 WearLog；删除 Person → 级联删其 WearLog；删除 Item → WearLog 不动（挂在 Outfit 上）。
- 存储：`wardrobe.json` 增加 `wearLogs[]`；旧 JSON 缺字段反序列化为空数组，向后兼容不 bump schemaVersion（同 it-017 `refImageFile` 先例）。
- 演示模式（it-015）：mock 仓库补 WearLog 种子（与既有 15 处种子对齐），打卡在演示下走内存仓库。

### 阶段B · 衣橱统计回顾页（W9）+ 年度衣橱长图

入口：W3 衣橱页标题行「共 N 件」右侧 📊 图标 → W9（回顾为低频页，不占常驻 Tab）。

```
┌───────────────────────────────┐
│ ‹ 衣橱回顾 · Leo  [今年 | 累计]  │
│  24 件 · 18 套 · 打卡 42 次      │ ← 三大数字（单品/穿搭/打卡）
│ ┌───────────┐┌───────────┐    │
│ │🏆 白衬衫    ││🥈 小白鞋   │ →  │ ← 最百搭 TOP3 横滑卡
│ │进过 9 套   ││6 套       │    │    （缩略图+穿搭数）
│ └───────────┘└───────────┘    │
│ 品类分布  ▉▉▉▉▉▉ 上装 8 …      │
│ 利用率    81% 单品上过身        │ ← 穿过≥1次占比
│ 闲置清单  5 件从没上过身 →       │ ← 二级页：缩略图网格
│ 出勤最高  「通勤简约」穿 6 次     │
│ [ 🎁 生成年度衣橱长图 ]          │
│ ────────────────────────      │
│ 衣柜提醒        （阶段C）        │
└───────────────────────────────┘
```

- 统计口径（纯 Kotlin `WardrobeRecapCalculator`，JVM 单测）：单品/穿搭/打卡计数、单品穿着次数与 lastWornAt（经 Outfit 间接聚合，派生不落盘）、最百搭 TOP3、品类分布、利用率、闲置清单（从未出现在任何 WearLog 关联 Outfit 的单品）、出勤最高穿搭、连续打卡天数。
- **年度衣橱长图**：封面（角色 emoji+名+年份）→ 三大数字 → 最百搭 TOP3 → 品类分布 → 精选成品图墙（今年打卡关联的成品图，最多 9 张宫格，缺图用 BodyCollage 占位）→ 结尾条。复用 App 内长图管线（it-002/014），存 `Pictures/Wardrobe`、分享双通道，年份可选今年/去年。按当前角色出图（多角色各出各的）。

### 阶段C · 好久没穿提醒

- `androidx.work` 每日一次（依赖变更记 ADR-019）：单品粒度——`穿着次数 ≥ 2` 且距 `lastWornAt ≥ N 天`（默认 90，可选 60/90/180）→「这件大衣 3 个月没穿了，想它吗？」点击 → W5 衣物详情。
- 每日至多 1 条、随机、通知文案带角色（「Leo 的白衬衫…」）。W9 底部开关 + 天数 chips，开启时请求 `POST_NOTIFICATIONS`，**默认关**。
- 新录入未穿过的单品不推（那是闲置清单的事）；演示模式 cancel 任务、入口置灰。

### 可选 · 价格字段与 CPW（可裁剪）

- `Item.price: Double?`（W4 表单可选字段）+ 单品穿着次数 → W5 详情显示「单次穿着成本 ¥X」（CPW）；W9 加「衣柜总价值」。数据量小、改动表单+详情两处；确认时决定是否并入本迭代。

## 验收标准

- 打卡：同日两条共存、改日期、撤销今日；删除 Outfit/Person 级联删 WearLog（Repository 假实现单测）
- 统计：伪造快照断言全部派生指标（含空数据、单品无打卡、并列 TOP3 边界）
- 长图：生成/存相册/分享三通道；无成品图时图墙用拼贴占位不空白
- 提醒：候选规则单测（恰好 N 天、未穿过不推、演示模式不注册）；模拟器实测通知→点击进详情
- `./gradlew assembleDebug test` 通过；W9 与长图样张截图对照验收
- **执行顺序注意**：本迭代与 it-016 阶段B（抠图接入）都动 wardrobe，两案不并行进行
