# it-051 · W6 导出生图表单的场景可见性与编辑式重排

- **日期**：2026-09-28
- **状态**：已完成
- **来源**：W6 真机截图反馈——“选场景的表单不明显，整个表单页很丑”
- **类型**：界面信息架构 + 视觉与交互优化

## 背景与动机

W6 是用户把当前穿搭交给生图 Agent 前的最后一步。现有实现将场景、氛围、季节、光线、构图五项收在“风格与场景维度（全部可选）”的折叠区中；折叠时仅显示一个数字徽标和箭头。用户无法从常态页面判断“场景”是否已设置、当前选择是什么，也没有足够明确的点击线索去修改它。

同一页还把人物描述、自定义要求和可编辑 Prompt 都做成相似的粗描边输入框。它们与预览、收藏/录入操作、底部导出动作处在同一视觉权重，造成“长图预览—生成设定—补充信息—导出”这个关键路径被大面积边框和长文本打散。

### 轻量 UI 走查结论（基于用户提供的 W6 截图 + 源码核对）

| 编号 | 级别 | 发现 | 证据/对表 |
|---|---|---|---|
| E1 | P1 | 场景选择的入口和当前值不可见，只能猜测“5”代表已选维度数。 | `ExportSheet.kt` 的五维 `DimensionChips` 被 `AnimatedVisibility(expanded)` 包住；与 DESIGN.md §2.5 的交互线索要求不符。 |
| E2 | P1 | 页面没有可辨认的“生成设定”主区，五个画面维度的语义被泛化标题抹平。 | 截图及 W6 当前线框；“场景”是 Prompt 的高价值参数，应有独立可扫读路径。 |
| E3 | P2 | 三个大尺寸描边框形制几乎相同，字段用途、优先级和可编辑范围难以区分。 | 截图；DESIGN.md §1 的层次应以留白/hairline 建立，而非大面积重边框。 |
| E4 | P2 | 预览、表单、Prompt、沉淀操作与导出操作的分组边界不够清楚，长页滚动时难以建立位置感。 | 截图与 `ExportSheet.kt` 内容列结构。 |

## 用户故事

- **US-52 · 可见的生图场景设定**：作为准备导出生图素材的用户，我能在不展开隐藏面板的情况下看见并修改当前场景；同时能一眼确认氛围、季节、光线与构图是否已设置。
- **US-53 · 有编辑秩序的导出表单**：作为用户，我能按“预览 → 画面设定 → 补充描述 → 校对文案 → 导出”的顺序完成操作，而不必在一堆同样的输入框中寻找下一步。

## 方案与交互

### W6 信息架构

```
┌──────────────────────────────────┐
│ ─────── 导出生图素材 ───────      │
│ [ 长图预览 ]                      │
│                                  │
│ 画面设定                          │
│ ┌ 场景                   咖啡馆 ›┐│  ← 常驻且优先
│ │  氛围      优雅正式            ││
│ │  季节      早秋                ││
│ │  光线      黄昏暖光            ││
│ │  构图      街拍视角            ││
│ └────────────────────────────────┘│
│ [展开的行下方：可横滑的单选 chips] │
│                                  │
│ 补充信息                          │
│ 人物描述（会记住上次）             │
│ [ 例如：短发，偏瘦，自然站姿      ] │
│ 自定义要求（可选，会记住上次）     │
│ [ 例如：不要改变鞋子的颜色        ] │
│                                  │
│ 生成文案                 可编辑    │
│ ┌────────────────────────────────┐│
│ │ …                               ││
│ └────────────────────────────────┘│
│                                  │
│ [收藏这套]        [录入成品图]     │
├──────────────────────────────────┤
│ [复制长图] [存相册] [分享]         │  ← 固定动作栏保留
│ [只复制文本（含单品清单）]          │
└──────────────────────────────────┘
```

1. 删除笼统的“风格与场景维度（全部可选）”总折叠入口。改为常驻的“画面设定”卡：第一行固定为更醒目的**场景**，其余四项以统一的“标签 / 当前值 / ChevronRight”行呈现。未选时明确显示“未设置”，而不是把缺省状态藏进计数。
2. 点任一行仅在**该行下方**展开可横滑的单选 Chip 列；同时关闭前一行。点击已选 Chip 可清空该维度，卡片即时更新为“未设置”。不新开 Dialog/BottomSheet，避免 sheet 嵌 sheet（DESIGN.md §2.5）。
3. 用户第一次打开 W6 时，若场景未选中，默认展开“场景”行；已选中则保持收起、值常驻可见。页面状态只在本次弹层期间保留，不改变现有维度值、记忆策略或 Prompt 生成逻辑。
4. 人物描述与自定义要求归入“补充信息”小节，采用常驻 label、轻 surface 底和 hairline；人物描述保留单行，自定义要求保留多行。输入框不再依赖灰色占位文字承担全部语义。保留“记住上次”行为。
5. Prompt 归入“生成文案”小节，字段标题右侧标明“实时生成 · 可编辑”；维持等宽字、150dp 编辑高度和实时生成行为。采用与其余字段一致的轻 surface 与 hairline。
6. 长图预览、附形象参考照开关、收藏/录入成品图和固定导出动作的功能、顺序、数据通道均不变；仅重新分组和调整视觉层级。

### 视觉与动效

- 遵循 wardrobe 的“时装编辑（print）”轴：预览为内容主角；“画面设定”是唯一具备轻 surface 容器的任务卡；`accent` 仅用于选中 Chip、焦点和主导出按钮，面积受 DESIGN.md §2.1 约束。
- 屏幕边距 20dp；分组间 28dp；设置行最小高度 52dp（含 ≥44dp 触控目标）；行内标签为 Sans Label、值为 Sans Body，避免小字号衬线。
- 展开/收起为 `AnimatedVisibility` + `EditorialMotion.smooth`，只作用于当前 Chip 行；不做卡片逐项弹跳。首次自动展开不播放额外入场编排；系统“移除动画”时直接切换。
- 选择成功仅给现有轻 tick/即时色态，不新增音效或彩屑。

## 验收标准

1. W6 常态可见“场景”以及其他四个画面维度的**当前值或“未设置”**；页面不再以仅含计数徽标的总折叠区作为唯一入口。
2. 场景行在视觉上先于其他维度，点按区域 ≥44dp，并明确表现可编辑性；场景未设置时首次打开自动展开其选项。
3. 任何维度点按后仅展开该行的单选 Chips；改选、再次点选清空、Prompt/长图实时更新均保持既有行为。展开任一维度时不出现嵌套弹层。
4. 人物描述、自定义要求与 Prompt 分别有可读的永久标签；前两者的“记住上次”语义不再只写在低对比 placeholder 中。数据持久化与生成的 Prompt 内容保持兼容。
5. 预览、形象参考开关、收藏/录入成品图、复制/存相册/分享/只复制文本的行为和固定底栏可达性不回归；键盘打开时底栏继续避让。
6. 浅色和深色均使用 `paper/surface/ink/inkFaint/accent/hairline` 六类 token；正文对比满足 DESIGN.md §2.2，accent 不做大面积铺底。
7. 完成 debug 构建与单测；模拟器分别验证：未设场景首次打开、已设场景编辑/清空、五维 Prompt 同步、键盘输入、复制/保存/分享、深浅色；截图与 DESIGN.md §2–§5 对表结论回填本文件。
