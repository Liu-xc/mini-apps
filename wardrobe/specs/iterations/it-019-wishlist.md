# it-019 · 心愿清单：想买单品 + 心愿穿搭（混搭预览与购入转正）

- **状态**：待确认（Leo）——「保存心愿穿搭」已获 Leo 拍板（2026-09-20）：「可以保存吧，属于心愿穿搭。不保存后面要再预览不好弄」
- **提案日期**：2026-09-20
- **范围**：新增 WishItem（想买单品）与 WishOutfit（心愿穿搭）两个实体及「心愿」页（W9）；搭配页槽位混入愿望单品做上身预览、可存为心愿穿搭反复回看；「已买到」一键转正，心愿穿搭买齐后一键升级为正式穿搭。不改变 Item/Outfit 既有语义
- **姊妹迭代**：eats it-008（吃喝玩乐+想吃愿望清单），同源需求（Leo 2026-09-20）：「把想吃的和想买的也加进来，可以进行预览、规划」；wardrobe it-018（穿搭打卡回顾）与本迭代相互独立
- **编号协调**：本提案与 it-018 均未实施。若本迭代先行，it-018 与本迭代并行实施（2026-09-20），it-018 先落笔占用 W9 / US-17~20 / ADR-018/019，本迭代实际占用 W10 / US-21~23 / ADR-020；若后实施则本迭代顺延。wardrobe 侧全局串行约束（不与 it-016 阶段B 并行）对本迭代同样适用

## 背景与动机

衣橱只管「已拥有」：种草的衣服/鞋/包没地方放，链接和商品图散落在备忘录与聊天记录里。更关键的是购前决策没有工具——买之前最纠结的是「这件能不能搭进我现有的衣橱」，现在只能靠脑补；拼出来的预览组合也没法保存，想再看一次效果只能重拼。

闭环四件事：

1. **种草有处安放**：想买的单品先录进来（名称+品类即可，商品图/链接/价格可选），集中管理。
2. **预览辅助决策**：愿望单品混进搭配页槽位与已有衣服组套，导出长图让生图 Agent 出上身效果图——「买了它搭我的白衬衫效果如何」有真实答案。
3. **心愿可沉淀**：含愿望件的组合**存为心愿穿搭**（Leo 拍板），随时回看、再次导出预览；愿望单品逐件买齐后一键升级为正式穿搭。
4. **转正不断档**：到手后一键转正为衣橱单品（字段预填、补拍实物照），种草→拥有无缝衔接。

## 方案

### 阶段A · 心愿单品（W9 单品段）

- 新实体 `WishItem`：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | String (UUID) | 主键 |
| personId | String | 所属角色 |
| category | WardrobeCategory | 复用 8 类枚举 |
| name | String | 必填 |
| color / desc | String? | 同 Item，可空 |
| price | Double? | 心理价位/标价，可空 |
| url | String? | 商品链接（淘宝/京东/得物分享链接等），展示时显示域名，点击 ACTION_VIEW 打开 |
| imageFile | String? | 商品图（**可选**——与正式 Item 照片必填不同；截图即可），无图用品类占位插画 |
| tags | List\<String\> | 复用风格/季节/场合预设 |
| purchasedAt | Long? | 购入时间；null = 未购 |
| purchasedItemId | String? | 转正后指向正式 Item（留档回溯） |
| createdAt / updatedAt | Long | |

- 存储：`wardrobe.json` 增加 `wishItems[]`；旧 JSON 缺字段反序列化为空数组，**不 bump schemaVersion**（同 it-017/it-018 先例）。
- 入口：W3 衣橱页品类 chips 行尾新增「🌟 心愿」图标 chip（未购计数角标）→ W9。
- W9「心愿」页，顶部分段 **`[🌟 想买单品] [👗 心愿穿搭]`**（默认单品段）：
  - 单品段：未购愿望按品类分组（组内按种草时间倒序）；卡片 = 图（或占位）+ 名称 + 价格 + 标签；FAB → 录愿望底部弹层（仅名称+品类必填）；点卡片 → 详情底部弹层（大图、信息、链接 chip 跳转、编辑、删除、**「✓ 已买到」**主按钮）。已购入的收进底部折叠小节「已购入 N」，默认收起，点开可跳 W5 查看转正后的单品。
- 演示模式（it-015）：mock 仓库补愿望种子（与既有 15 处种子对齐），愿望写操作走内存仓库。

### 阶段B · 混搭预览 + 存为心愿

- W1 搭配页顶部（🎲 旁）新增「🌟」开关按钮：「混入心愿」（默认关，**仅会话内记忆不持久化**，同 it-017 开关先例）。开启后各品类槽位数据源 = 衣橱单品 + 该品类未购 WishItem。
- 愿望卡视觉：「想买」角标 + 虚线描边 + 降低饱和度，与正式单品一眼可辨；序号胶囊 ‹ n/m › 照常，槽位滑动/🎲 随机一套均参与。
- 组合中含愿望件时：
  - 「📋 复制长图」照常：长图该槽位照拼（商品图），文案在愿望件描述后追加「（种草未购入单品，生成时一并上身展示）」——预览上身效果的主通道；
  - 底部第二按钮从「☆保存这套」**变为「🌟 存为心愿」**：创建 WishOutfit（去重规则同 US-08：itemIds 集合 + wishItemIds 集合相同即不重复）；
  - 无愿望件的组合保持原「☆保存这套」逻辑不变。
- 生图完成后的效果图可录入该心愿穿搭（`previewImages`，与正式穿搭成品图同构），详情里回看上身效果。

### 阶段C · 心愿穿搭管理与购入转正

- 新实体 `WishOutfit`：`id` · `personId` · `itemIds`（已有单品部分）· `wishItemIds`（愿望单品部分）· `tags` · `previewImages: List<OutfitImage>` · `createdAt/updatedAt`。**不变量：至少含一件愿望单品**（纯已有件组合应存正式 Outfit）。
- W9 穿搭段：心愿穿搭卡（合成图/预览图 + 成员数 + 「还差 n 件」）；点开详情：成员列表（已有件→W5，愿望件→详情弹层）·「📋 复制长图」再次导出 ·「→ 去预览」（恢复该组合到 W1 各槽位并自动开启混入开关）· 删除。
- **转正联动**：WishItem「✓ 已买到」→ 转正表单（预填全部字段，照片沿用商品图或补拍实物）→ 创建 Item + 回填 `purchasedAt/purchasedItemId`；所有含该愿望件的 WishOutfit 自动把它移入 itemIds（详情提示「2 套心愿穿搭已更新」）。
- **一键升级**：心愿穿搭的 wishItemIds 全部转正后，详情出现高亮「👗 升级为穿搭」→ 创建正式 Outfit（继承 itemIds/tags，previewImages 移交 effectImages）→ 心愿穿搭移除。部分转正的组合随时可继续预览。
- 级联不变量追加：删除 Person → 级联删其 WishItem/WishOutfit 及图片文件；删除 Item → 从 WishOutfit.itemIds 移除；删除 WishItem → 从各 WishOutfit.wishItemIds 移除（组合保留，若因此变空则该心愿穿搭按不变量清洗移除）。

### 「规划」的边界

Leo 需求中的「预览、规划」：预览 = W9 清单视图 + 混搭上身预览 + 心愿穿搭回看；规划 = 场景标签 + 预览组合的购前决策（「为了下周约会值不值得买这件」）。未来穿搭排期（周历式「哪天穿哪套」）是 it-018 WearLog 的镜像方向，不在本期；如需要可另立迭代。

## 验收标准

- Repository（假实现）单测：WishItem/WishOutfit CRUD、删 Person 级联（含图片物理删除）、保存去重（itemIds+wishItemIds 集合判等）、转正联动（含该件的 WishOutfit 自动移入 itemIds、全转正后可升级）、删 WishItem/Item 后 WishOutfit 的引用清洗、心愿穿搭至少一件愿望单品的不变量

- W9：录愿望（仅名称+品类可保存）、分段切换、链接跳转、已购入折叠小节；删除愿望二次确认且图片物理删除
- 旧数据兼容：无 wishItems/wishOutfits 字段的旧 JSON 加载为空清单，其余功能与升级前一致（单测）
- `./gradlew assembleDebug test` 通过；W9 与混搭预览样张截图对照验收
