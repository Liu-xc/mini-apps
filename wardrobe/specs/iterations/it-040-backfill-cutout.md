# it-040 · 已录入衣物补抠（重新去背景）

- **状态**：提案，待 Leo 确认后开工
- **来源**：it-016 §4.1「仅录入时提供，已录入衣物不补抠（演进候选）」+ US-15 末条 AC
- **关联**：新增 **US-40**；改写 US-15「编辑既有衣物不出现去背景入口」AC；新增 **ADR-023**（补抠输入与回退策略，接 ADR-016）

## 背景与动机

it-016 的去背景只在录入（W4）时提供，先于抠图录入的旧衣物永远没有干净的透明底——而卡面、合成长图、导出的观感全靠透明底。数据模型只有一个 `imageFile`，且 ADR-016 拍板「保存后原图即弃」，所以：

**补抠唯一可用的输入 = 当前这张已抠图**（带 alpha 的 lossy WebP q82）。

这带来三个必须正视的风险，也是本提案分两阶段的原因：

1. **分布外输入**：u2netp 是在真实照片上训练的显著性模型，「透明底合成图」它没见过；透明区 RGB 经 WEBP_LOSSY 编码后是否保真（还是被清零成黑底）spec 与代码均无记录。
2. **代际损失**：每次补抠 = 解码 → 重编码 q82，反复补抠阶梯式劣化，且无原图可回退。
3. **无状态标记**：`Item` 没有「是否已抠过」字段，入口要靠 alpha 检测启发式判断当前图状态。

## 用户故事

- **US-40a**：作为用户，我想对已录入的衣物补做/重做去背景，让旧卡片也能变成干净的透明底。
- **US-40b**：作为用户，补抠前系统先备份当前图，我对新结果不满意可以一键还原——不会因为补抠把唯一一张图搞坏。

## 方案

### 阶段 A · spike 先行（不碰 UI，先验证可行性）

用现有管线自测，产出小报告（`reports/2026-09-XX-cutout-recut-spike/`）：

1. **透明区 RGB 保真**：取已抠样张（it-016 报告的透明底衣物图），decode 后统计 alpha<255 区域的 RGB 分布——是否被编码器清零/偏移。
2. **二次分割质量**：把已抠图再过一遍 u2netp，对比前后 alpha（IoU / 主体覆盖率 / 边缘），样张目测（白底商品图、平铺、人穿衣服三类）。
3. **代际损失**：连续补抠 3 次，记录画质劣化。

**放行门槛**：透明区 RGB 不被清零（或清零但二次分割结果仍合格）+ 样张目测可接受。不达标 → 阶段 B 不开工，回来找 Leo 换方案（候选：放宽为「只对无 alpha 的原图补做去背景」，或放弃补抠维持 it-016 边界）。

### 阶段 B · W5 接入

**入口**：W5 衣物详情大图下方新增操作行（与 W4 同构的「去背景状态条」视觉语言，05-design-system 既有棋盘格母题）：

- **alpha 检测**（启发式，无需加字段）：解码当前图，统计 `alpha < 255` 的像素占比。
  - 占比 ≥ 阈值（拟 5%，spike 校准）→ 判定「已抠图」→ 按钮文案「**重新抠图**」
  - 否则 → 判定「原图」→ 按钮文案「**去背景**」（数据包导入未抠图、演示素材走这条）
- 演示模式素材、数据包图片同样适用（走 `ImageEditStore.cutoutTo` 同一管线）。

**会话内备份与回退**（US-40b，替代已不存在的「原图锚点」）：

```
点「重新抠图/去背景」→ ① 复制当前图为会话内备份（内存/临时文件）
                    → ② 推理（≤1s，引擎复用，预热逻辑同 W4）
                    → ③ 棋盘格预览 + 「保留」/「还原」
「保留」→ 新图覆盖落盘（uuid.webp 同名覆盖），备份丢弃
「还原」/ 返回未确认 → 恢复备份，原图分毫不动
失败 → toast（措辞同 W4：「去背景失败：这张照片先保持原样」），备份恢复
```

- **跨会话不可还原**（无原图，如实呈现）：确认保留后不设「撤销补抠」——ADR-023 记录此边界。
- 入口常驻（不做「已抠过就藏起来」——补抠的诉求正是重做）。

**W5 状态条**：已抠态显示「已去背景 · 透明底」+「重新抠图」按钮（与 W4 的 Surface+CheckCircle 同款）；原图态显示「去背景」OutlinedButton。触控 ≥44dp（it-033 基线），遵循 W5 白底二级页状态栏规则（it-034）。

## 验收标准

1. spike 报告落档，三项数据齐全，放行/不放行结论明确。
2. W5 大图下出现状态条：已抠图 → 「重新抠图」、原图 → 「去背景」，文案与实际状态相符。
3. 补抠全流程：备份 → 推理 → 棋盘格预览 → 保留/还原，两条路径数据正确（覆盖后 `Item.imageFile` 不变、文件内容更新；还原后文件逐字节还原）。
4. 推理失败/中途退出：原图不动，无残留备份文件。
5. 补抠后的衣物在 W3 卡片、W1 合成图、W6 导出长图中渲染正常（透明底无黑底）。
6. 反复补抠（≥3 次）无崩溃；代际损失按 spike 结论如实呈现（不做「可无限重抠」承诺）。
7. 既有回归：录入抠图（W4）、编辑保存、删除、数据包导入不受影响。
8. specs 同步：01-user-stories（新增 US-40 + 改 US-15 末条 AC）、02-wireframes（W5 操作行注记）、05-design-system（如状态条有新变体）、06-decisions（ADR-023）、CHANGELOG 一行。

## 待确认决策（Leo）

1. **放行门槛的裁决权**：spike 若不达标，我建议「原图态才给入口、已抠图态隐藏」保守收场——是否接受这个降级，还是宁可整个 it-040 作废。
2. **代际损失的呈现**：我建议不做次数限制（自用场景，样张说话），只在 spike 报告里记录劣化曲线——是否同意。
3. **入口常驻 vs 已抠隐藏**：我推荐常驻（见方案）；如果你想减少 W5 常驻控件，可改为只在「原图态」出现 + 已抠态收进顶栏溢出菜单。
