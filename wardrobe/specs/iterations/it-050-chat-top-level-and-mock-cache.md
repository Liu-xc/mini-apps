# it-050 · 顶层穿搭顾问、未配置只读与 Mock BYOK 缓存

- **日期**：2026-09-28
- **状态**：已实现；构建与单测通过，Mock 真 Key 首发/缓存命中待设置测试 Key 后验收
- **来源**：聊天能力入口与测试效率需求
- **类型**：信息架构调整 + AI 测试能力增强

## 背景与动机

当前 W12「穿搭顾问」仅能经 W11 设置页进入，且演示模式强制使用固定离线 `FakeChatModel`、禁用 Key。这使聊天能力不像应用的一等入口，也使开发/验收人员无法在确定的 Mock 衣橱数据上使用自己的模型 Key 做真实回归。当前未配置 Key 时仍会先把用户消息写入会话，之后才报 Auth 错误；这不是可预期的只读体验。

本迭代将聊天放入首页底部导航。未配置可用模型连接时，聊天 Tab 只展示已保存的对话历史，不提供创建或发送入口；配置完成后才允许进入/创建可交互对话。Mock 数据环境将拥有与真实数据环境隔离的测试连接配置，并为相同请求缓存模型结果，降低重复走查的时间与 Key 消耗。

## 用户故事

- **US-50 · 顶层穿搭顾问与未配置只读**：作为用户，我可以从底部导航直接进入「顾问」；若尚未配置可用模型，我仍能阅读已有聊天记录，但不能创建或发送新对话。
- **US-51 · Mock 数据下的真实模型回归与缓存**：作为测试者，我可以在 Mock 数据环境配置独立的 BYOK Key；相同的测试请求优先复用本机缓存结果，以更快、更省额度地重复走查。

## 验收标准

1. 首页底部导航为四项：搭配、穿搭记录、衣橱、顾问；顾问是顶层 Tab，不再依赖 W11 的唯一入口。W11 仍保留模型连接设置入口和「打开顾问」快捷入口。
2. 顾问 Tab 默认是**会话列表**：每项展示标题/最近一条内容/更新时间；点已有项进入只读或可交互的会话详情。没有任何记录时展示符合 DESIGN.md 的空状态。
3. 没有已保存且可用的模型 Key 时，会话列表与既有会话内容均可读；隐藏/禁用「新对话」和输入发送区，并在页内说明「配置 API Key 后可发起对话」，主行动直达 W11。不得先写入用户消息再报未配置错误。
4. 配置可用 Key 后，顾问 Tab 显示「新对话」入口；新会话与既有会话均可发送、停止、重试、复制、重新生成，保留现有工具调用、流式、错误分类与会话持久能力。
5. Mock 数据环境有**独立于真实衣橱环境**的模型连接配置：测试者可在 W11 配置/清除 Mock Key，Key 用 Android Keystore AES-GCM 保存、界面仅显示 mask、数据包导出永不包含 Key；不得读取或复用真实环境 Key。配置后 Mock 环境使用真实模型与真实的只读衣橱工具；未配置时同样只读，不可用假模型绕过配置要求。
6. Mock 真实模型调用支持本机结果缓存：命中条件至少包含 Mock 数据版本、厂商/模型、system prompt、工具定义版本与完整请求上下文；命中时不发网络请求并以明确但低打扰的「已使用测试缓存」状态呈现。缓存只保存本机私有目录、不得进入数据包/日志；切换 Key、模型或 Mock 数据版本时不得错误复用；提供测试环境内「清除顾问缓存」操作及确认。
7. 缓存未命中、网络/模型失败、停止或工具结果变化时不得写入完整缓存；缓存写入使用原子文件替换。缓存容量与 TTL 有上限并自动回收，避免无限增长。
8. 单元测试覆盖：未配置不会追加会话消息；Mock/真实 Key 命名空间隔离；缓存命中零网络、关键变化必 miss、失败/取消不写入、清除缓存生效。完成 debug 构建、单测与模拟器走查（配置前只读、配置后新建/发送、Mock 真调首发与缓存命中）。

## 交互与页面范围

- **W12 顾问会话列表（新增顶层 Tab）**：底栏直达；空态或会话卡列表；未配置时显示只读提示与「去配置」；配置后显示「新对话」。
- **W13 顾问会话详情（由原 W12 演进）**：保留现有消息列表、工具条、流式和回复动作。未配置时无输入栏，仅渲染历史；配置后允许发送。顶栏返回会话列表，而非返回设置页。
- **W11 设置页**：保留连接配置及打开顾问快捷入口；在 Mock 环境明确标注「测试连接」，Key mask 与缓存管理只作用于该环境。
- **动效/视觉**：新增 Tab 遵循 `DESIGN.md`：Material `SmartToy`（或等价）图标、≥44dp 命中区；列表常规切换用 220ms crossfade，不为每张会话卡附加 bouncy 入场；未配置空态采用图形 + 说明 + 行动按钮，不只放一行文字。

## 技术方案

1. 将现有全局单 `wardrobe-chat` 会话升级为带元数据的会话索引（标题、创建/更新时间、最近摘要）；会话消息仍由 `FileSessionStore` 原子持久化。为历史兼容，将旧单会话迁移/登记为一条可读记录；不改 `WardrobeData` schema，也不进入衣橱数据包。
2. 在导航中新增 `Tab.CHAT`，`Routes.CHAT_LIST` 承载顶层列表，原 `Routes.CHAT` 调整为带 `sessionId` 的详情路由；Deep link、错误「去设置」和 W11 快捷入口按新路由回跳。
3. `ChatViewModel` 分拆列表状态与会话详情状态，并在 `send` 前以连接可用状态硬拦截（UI 与 ViewModel 双层）。会话详情的只读状态由连接状态实时决定。
4. 连接配置按运行数据域分命名空间：真实环境保持既有 Keystore 存储；Mock 环境使用另一个 Keystore alias/SharedPreferences 名称与独立 prefs keys，绝不从真实域回退读取。此项修订 it-041/ADR-024 的「演示模式一律离线、禁用 Key」红线，需新增 ADR。
5. 新增 `data/mock` 内部的测试缓存仓库/装饰器，包裹真实 `ChatModel`：对规范化请求生成 SHA-256 指纹，单步结果先暂存，只有整个 `AgentRunner` 成功完成才原子提交；模型失败/整轮取消即丢弃所有本轮暂存。缓存只在 Mock+已配测试 Key 时启用。缓存接口须可注入，以 JVM 测试用内存 fake 覆盖。
6. 保持默认演示开箱零外呼：Mock 模式无测试 Key 时顾问只读；只有用户在 Mock W11 主动保存测试 Key 后才可发起网络对话。

## 待确认决策

1. **已确认**：采用多会话历史列表，原消息页成为详情（W13）。
2. **已确认**：Mock Key 只在用户主动配置后真实外呼，且与真实衣橱 Key 严格隔离；这是对 ADR-024 演示模式零外呼红线的受控例外。
3. **已确认**：缓存最多 100 条或 50 MB、TTL 7 天；命中以低调状态条提示，提供手动清除。
