# it-049 · 穿搭调整、副本与透明素材

- **日期**：2026-09-28
- **状态**：已交付验收包
- **来源**：Mock 包验收反馈与三张真机截图
- **类型**：交互增强 + 呈现修复

## 背景与动机

验收截图显示三处直接影响穿搭编辑与浏览的体验问题：人体拼贴里的不透明商品图形成突兀白方块；W7 拼贴的缺失品类只是占位，无法从详情页补齐或调整；有成品图的 W7 详情仍按固定比例裁切图片。用户还需要保留原穿搭并复制一份继续试搭。

## 用户故事

- **US-48 穿搭详情调整与副本**：我可以从 W7 空槽直接开始补搭、替换或移除单品；创建副本后可以独立调整，原穿搭保留。
- **US-49 衣物透明底与成品图完整展示**：新录入的衣物默认去背景，拼贴使用透明图层融入底色；穿搭成品图在 W7 完整展示。

## 验收标准

1. W4 选择新照片后自动生成透明底候选；推理失败时原图仍可保存，并可手动重试；候选可还原，保存后采用透明图。
2. 内置演示衣物图为带 alpha 的抠图素材；首次启动新版本时刷新缓存中的同名内置图片（不覆盖 UUID 临时图）；W7/W8 拼贴中的衣物不再带独立白色方块底，空槽仍清楚可辨。
3. W7 无成品图时，点击拼贴空槽会进入编辑态并打开适用品类的衣物选择；编辑态可点已穿单品替换、移除，可补充包/配饰；保存生效，取消丢弃草稿。非编辑态单品列表仍可进入 W5。
4. W7 创建副本后打开新记录；副本继承角色、单品和标签，不复用旧成品图、评论或打卡；新副本可继续补搭/替换，原记录不变。
5. W7 成品图使用完整适配，不裁切主体；多图横滑、页码提示和删除入口保留。
6. 无数据格式迁移；`01-user-stories.md`、`02-wireframes.md`、`05-design-system.md` 与 `CHANGELOG.md` 保持一致。

## 影响范围

- W4：`ItemEditScreen` 选择图片后的抠图候选与回退。
- 拼贴：`BodyCollage` 空槽/已穿位置的编辑回调和透明图层呈现。
- W7：`OutfitDetailScreen` 编辑草稿、同角色衣物选择、副本入口与成品图 Fit。
- `AppViewModel`：更新穿搭单品与创建独立副本；路由打开副本详情。
- `AppContainer`：演示内置图片 revision 升级刷新。
- 演示素材：`wardrobe.json` 引用的 `item-*.png` 透明化。
- 无数据模型、存储格式、依赖或 ADR 变更。
