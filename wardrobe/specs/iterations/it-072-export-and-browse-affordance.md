# it-072 导出核对与浏览可发现性

- 状态：**已实施**（2026-09-30）
- 提出日期：2026-09-30
- 涉及应用：wardrobe
- 依据：[UI 走查报告](../../../reports/2026-09-30-wardrobe-ui-audit/wardrobe-ui-audit-2026-09-30.pdf)

## 背景与动机

2026-09-30 的最新 Debug 构建走查覆盖了搭配、衣橱、单品详情、导出、穿搭记录与顾问关键状态。主流程无 P0 阻断，但有四处 P1 可发现性问题：长图首屏预览不可读、单品关联穿搭缺少目的地线索、记录页卡组压住历史列表入口、顾问未配置态的恢复动作重复且不够明确。

用户于 2026-09-30 明确要求“实施优化”，视为本提案确认。

## 涉及的用户故事

- **US-58**：用户可从单品、搭配和顾问推荐导出可交给生图 Agent 的素材。
- **US-24 / US-25**：用户可浏览已保存穿搭，并从关联单品回到完整穿搭。
- **US-42**：用户配置模型后可发起穿搭顾问对话。
- **US-54 / US-55**：黑白灰视觉一致、中文排版有清晰层级。

## 提案内容

1. **W6 导出面板**：首屏预览下方新增具名次级动作「查看完整长图」，点击进入既有全幅可滚动核对态；预览与动作都保留原有点击行为，图标不再是唯一线索。
2. **W5 单品详情**：关联穿搭改为有「穿搭记录 · 点开看整套」说明的卡片，保留整卡点击；仅一个关联结果时也明确其目的地。
3. **W8 穿搭记录**：卡组高度收紧，提前露出「全部 N 套」和首行历史卡；筛选标签行继续采用右缘渐隐，筛选后标题显示「筛选 · 1」反馈。
4. **W13 顾问未配置态**：只读空态保留一次说明，移除底部重复文案，改为全宽实心「去配置 API Key」主按钮（触控 ≥44dp）。

## 验收标准

1. W6 首屏可见「查看完整长图」文字动作，点击后显示原尺寸、可纵向滚动的预览；关闭回到原表单位置。
2. W5 每张关联穿搭卡可见「点开看整套」，点击仍进入正确 W7。
3. W8 首屏同时看见卡组、记录总数和至少一行历史卡；随机翻一套、分页与筛选不回归。
4. W13 无 API Key 时显示单个主要恢复按钮；按钮进入设置，已配置时不显示。
5. 日间/深色主题截图无溢出、无低对比关键文案，交互目标满足 DESIGN.md §2.5；`./gradlew test` 与 `assembleDebug` 全绿。
