# it-004 · 搭配页直接保存穿搭 + 组合去重检测

- **状态**：已完成（QA 模拟器验证通过）
- **提案日期**：2026-09-20
- **来源**：用户需求（2026-09-20）——「需要支持将当前的组合保存为一套穿搭，并且需要检查当前这套穿搭是不是已经保存过了」

## 背景与动机

it-001/003 的「收藏这套」藏在导出面板（W6）底部，主流程太深；且每次点击都会**新建**穿搭记录——同一组合反复保存会产生重复条目。用户需要在搭配页（W1）一眼看到「当前这套是否已保存」。

## 方案

1. **W1 底部栏改版**：`[📋 复制长图] [☆ 保存这套]`（原 ↗ 分享入口移除，分享在导出面板内仍可用）
2. **去重判定**：当前各槽选中（按组合记忆的落定值）的 itemId 集合，与该角色已有穿搭的 itemIds 集合**做集合相等比较**（顺序无关）：
   - 未保存 → 按钮为 `☆ 保存这套`，点击创建（tags 为空，可在 W7 补打标）→ 变 `★ 已保存`
   - 已保存 → 按钮为 `★ 已保存`，点击**跳转该穿搭详情（W7）**（看成品图/评论/打标），不再创建
3. **统一去重入口**：导出面板的「收藏这套」走同一查重逻辑（已存在则复用并更新标签，不重复建）
4. 域层新增查询 `WardrobeData.outfitWithItems(personId, itemIds)`（集合相等、角色隔离）

## 验收标准

- Given 当前组合未保存，When 点 ☆，Then 创建穿搭、按钮变 ★ 已保存、穿搭记录出现该套
- Given 已保存的组合（槽位滑回原组合），Then 按钮自动显示 ★ 已保存；点击进入对应 W7 详情
- Given 导出面板内点收藏同一组合，Then 不产生重复记录
- 单测：集合相等（乱序同集合 ✓、多一件/少一件 ✗、跨角色 ✗）
- QA 模拟器全流程实测

## 影响范围

- domain/model/Queries.kt（+outfitWithItems）+ 单测
- ui/AppViewModel.kt（saveOutfitDedup）、ui/outfit/OutfitScreen.kt（底部栏 + 已保存状态）、ui/outfit/ExportSheet.kt（收藏去重）
- MainActivity（onOpenOutfit 路由透传）、specs/01（US-08 修订）、02（W1 底部栏）

## 验证记录

- 单测 +4（集合相等/多件少件/跨角色/多条取最新）全绿；构建 ✅
- QA 模拟器实测：保存前 ☆ → 保存后 ★（落盘 1 条、2 单品）→ 点 ★ 跳 W7 详情 ✓ → 返回仍 ★ ✓ → 杀进程重启后仍 ★（组合记忆恢复即命中去重）✓ → 全程无重复记录 ✓
- 过程中发现并修复：初次实现用 `currentSelection()`（读 pager 当前页）判定，返回页面时 pager 重建未就绪会误判为未保存且被 remember 缓存；改为**由组合记忆（slotSel 落定值）推导当前组合**，与 pager 注册时机解耦且响应式更新
- 导出面板「收藏这套」同走去重（已存在则复用+更新标签）
