# 01 · 用户故事（User Stories）

> 状态：it-001 起草（2026-09-23）

## US-01 选模型开局

**作为**使用者，**我想**为红黑双方各任选一个 provider/model（含自定义 OpenAI 兼容 endpoint），**以便**对比任意两个模型。

- AC-1：下拉列出 `~/.pi/agent/models.json` 的自定义 provider + pi 内置 presets（zai/xiaomi/deepseek/openai/…），每方可独立选择。
- AC-2：点「开局」服务端 spawn 两个独立 session 的 pi 子进程，棋盘回到初始局面。
- AC-3：key 缺失时开局失败并在 UI 显示可读错误（指明缺哪个 env / 配置），不崩、不泄 key。

## US-02 实时观战与思考流

**作为**观众，**我想**实时看到棋盘落子、双方模型的思考/回复流、中文记谱，**以便**理解每步棋怎么来的。

- AC-1：落子后棋盘即时更新，着法表追加一行「炮二平五」式中文记谱。
- AC-2：当前行棋方的 text/thinking 流式出现在其思考栏。
- AC-3：模型输出非法走法时，思考栏可见纠错重试过程（≤3 次），第 3 次仍非法判负。

## US-03 暂停 / 单步 / 手动代走

**作为**观众，**我想**暂停、单步推进，或在任一方手动落子，**以便**研究局面或救活卡死的对局。

- AC-1：暂停后当前回合完成即停；单步只推进一个回合。
- AC-2：在棋盘点子可代任一方走（合法才生效），走完轮到模型。
- AC-3：模型静默超时（默认 120s 无输出；持续流式思考不计时）自动重试 1 次，仍无输出判负，UI 有明确提示。

## US-04 记分板与换先连战

**作为**记分者，**我想**多局循环并可换先，**以便**公平累计「谁比较聪明」。

- AC-1：终局（将死/困毙/和棋）后记分板更新 W/D/L，红黑模型名对应累计。
- AC-2：可开「连战换先」：上一局黑方下一局执红。
- AC-3：对局结束或重开时 pi 子进程被回收，无孤儿进程。

## US-05 导出棋谱

**作为**记录者，**我想**把对局导出为文本棋谱，**以便**存档或分享。

- AC-1：导出包含双方模型名、结果、完整中文记谱序列（可回放 FEN 序列）。
- AC-2：导出为纯文本/PGN 风格，浏览器下载，不含任何 key 信息。
- AC-3（it-002）：每手附 jev 评估值（红/和/黑 概率），如有。

## US-06 每手胜率评估与曲线（it-002）

**作为**观众，**我想**每手落子后看到 Jev 模型给出的红黑胜率，并有一条随对局生长的胜率曲线，**以便**量化地判断谁占优、谁更聪明。

- AC-1：每手落子后（含手动代走）异步评估，红/和/黑概率之和为 1，随 `eval` 事件实时回填与广播；评估失败静默跳过该点，绝不阻塞对局。
- AC-2：侧栏「胜率曲线」面板：红胜率实线 + 黑胜率虚线 + 50% 基线 + 末端百分比标签与图例（含置信度）；刷新页面后曲线随 state 全量恢复。
- AC-3：`JEV_API_KEY` 存于 `xiangqi/.env.local`（gitignore）；缺失时面板提示「未配置」且对局不受影响；key 永不进 git/HTTP 响应/日志。
- AC-4：`JEV_DISABLED=1` 可整体关停（假模型冒烟用，不打真 API）。
- AC-5（修订）：评估按局可选——控制条勾选框，开局参数生效、运行中可即时开关，关闭后新落子不评估。
- AC-6（修订）：发给 Jev 的 prompt 全英文（state/instructions/criteria，历史走 ICCS），中文记谱与 UI 文案不进 prompt。
